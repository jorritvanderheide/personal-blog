When people first encounter permacomputing, they often think it means using old hardware. Running a 486 as a web server. Squeezing every cycle. That is part of it, but it misses the point.

## The actual principles

Permacomputing borrows from permaculture: observe, then intervene minimally. Use what is already there. Design for longevity, not novelty. The core question is not "how do I make this faster" but "how do I make this last."

Applied to computing, this means: choose technologies that can be maintained by small groups of people. Prefer simple systems over complex ones. Accept constraints instead of engineering around them. Write software that runs on the hardware people already have.

## Why "just use old computers" misses the point

A Raspberry Pi running a static site is permacomputing. A modern laptop running only the software it needs is permacomputing. A phone kept for five years instead of two is permacomputing. The hardware age is irrelevant. What matters is the relationship: are you maintaining and adapting what you have, or are you on the replacement treadmill?

## The uncomfortable implication

Most of the software industry exists to create demand for new hardware. Permacomputing rejects that cycle entirely. It is not a technical movement — it is a refusal.
